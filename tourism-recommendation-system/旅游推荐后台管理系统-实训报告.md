# 旅游推荐后台管理系统 实训报告

> 基于 **Django + Vue3（django-vue3-admin / dvadmin3）** 前后端分离框架，结合携程旅游景点数据集搭建的旅游推荐后台管理系统。
> 实现了旅游数据的导入与管理、推荐功能接口、后台可视化大屏的完整闭环。

---

## 一、项目概述

### 1.1 项目背景

随着在线旅游（OTA）行业的快速发展，海量旅游景点数据需要被结构化存储、统一管理，并在此基础上为游客提供智能化的景点推荐。本项目以真实爬取的**携程旅游景点数据集**（`旅游景点数据集.xlsx`，4.8 万余条记录）为数据源，基于成熟的开源后台管理框架 **django-vue3-admin（dvadmin3）**，构建了一个集「数据导入 → 数据管理 → 推荐服务 → 可视化分析」于一体的旅游推荐后台管理系统。

### 1.2 项目目标

1. 完成旅游景点数据的**批量导入**与**增删改查管理**；
2. 提供**推荐功能接口**（综合推荐、热门排行、相似推荐）；
3. 提供**统计聚合接口**与**可视化大屏**，直观展示数据分布；
4. 依据项目自带的启动文档完成**环境配置与前后端启动**，保证系统可正常访问。

### 1.3 主要功能

| 功能模块 | 说明 |
|---|---|
| 旅游数据导入 | 一键读取 xlsx，批量写入 MySQL（48,127 条） |
| 景点管理 | 列表查询（分页/搜索/过滤）、新增、编辑、删除、图片预览、详情跳转 |
| 综合推荐 | 基于热度、评论分、评论量的加权综合评分排序 |
| 热门排行 | 按热度评分降序的景点排行榜 |
| 相似推荐 | 基于景点标签的相似景点推荐 |
| 可视化大屏 | 指标卡 + ECharts 图表（地区/等级/标签/价格分布）+ 推荐榜单 |
| 权限管理 | 复用框架 RBAC 权限体系，菜单/按钮权限细粒度控制 |

## 三、系统总体设计

### 3.1 系统架构

系统采用前后端分离架构：

```
┌─────────────┐   HTTP/JSON (JWT)   ┌──────────────────────┐   MySQL  ┌─────────────┐
│   Vue3 前端  │ ──────────────────▶ │   Django + DRF 后端   │ ───────▶ │   MySQL 8.0 │
│  (端口 8080) │ ◀────────────────── │     (端口 8000)       │          │ 旅游景点表   │
└─────────────┘                      └──────────────────────┘          └─────────────┘
```

- **前端**：Vite 开发服务器（8080 端口），通过 `VITE_API_URL` 指向后端，动态菜单由后端返回；
- **后端**：Django 开发服务器（8000 端口），统一接口前缀 `/api/`，JWT 鉴权；
- **数据层**：MySQL 8.0，表前缀 `dvadmin_`。

### 3.2 目录结构（自建模块部分）

```
django-vue3-admin/
├── backend/
│   ├── conf/env.py                      # 环境配置（数据库/Redis/功能开关）
│   ├── application/                     # 项目配置（settings / urls）
│   ├── dvadmin/                         # 核心框架（system 系统管理 / utils 工具）
│   └── tourism/                         # ★ 自建：旅游推荐模块
│       ├── models.py                    #   景点数据模型 ScenicSpot
│       ├── serializers.py               #   序列化器
│       ├── filters.py                   #   过滤器
│       ├── views.py                     #   视图集（CRUD + 推荐 + 统计）
│       ├── urls.py                      #   路由
│       ├── management/commands/import_scenic.py   # 数据导入命令
│       └── fixtures/initialize.py       #   菜单/按钮权限初始化
└── web/
    └── src/views/tourism/
        ├── scenic/                      # ★ 景点管理页面（FastCrud）
        └── recommend/                   # ★ 旅游数据大屏（ECharts）
```

## 五、后端功能实现

### 5.1 数据模型

`tourism/models.py` 中定义 `ScenicSpot` 模型，字段与数据集 22 列一一对应，并对高频查询字段（`name`、`region_name`、`level`、`hot_score`）建立索引。

### 5.2 数据导入（`import_scenic` 管理命令）

编写 Django 管理命令，使用 `openpyxl` 流式读取 xlsx，按表头动态映射字段、类型转换、分批 `bulk_create`（每批 2000 条）：

```bash
python manage.py import_scenic           # 默认导入
python manage.py import_scenic --truncate   # 清空后重新导入
```

### 5.3 接口设计（`/api/tourism/scenic/`）

| 接口 | 方法 | 说明 |
|---|---|---|
| `/api/tourism/scenic/` | GET/POST | 列表查询（分页/搜索/过滤）/ 新增景点 |
| `/api/tourism/scenic/{id}/` | GET/PUT/DELETE | 单例查询 / 编辑 / 删除 |
| `/api/tourism/scenic/recommend/` | GET | 综合推荐 |
| `/api/tourism/scenic/top/` | GET | 热门景点排行 |
| `/api/tourism/scenic/similar/` | GET | 相似景点推荐（基于标签） |
| `/api/tourism/scenic/stats/` | GET | 可视化统计聚合 |
| `/api/tourism/scenic/regions/` | GET | 地区列表 |

### 5.4 推荐算法

**综合推荐得分**采用加权模型，将热度评分、评论分、评论数量归一化到 0–10 区间后加权求和：

```
综合得分 = 0.5 × 热度评分 + 0.3 × (评论分 × 2) + 0.2 × min(log₁₀(评论数+1) / 6 × 10, 10)
```

- **热门排行**：按热度评分降序，评论量兜底；
- **相似推荐**：以某景点的标签为基准，匹配共享标签的其他景点，再按热度/评论量排序。

### 5.5 统计聚合（`stats` 接口）

通过 ORM 聚合（`Count`/`Sum`/`Avg`）与 Python 标签解析，返回地区分布、等级分布、类型分布、热门标签、价格区间、评论量 TOP 城市等指标，供大屏渲染。

### 5.6 菜单与权限初始化

`tourism/fixtures/initialize.py` 随 `python manage.py init` 自动执行，幂等地创建：

- 一级目录「旅游推荐」→ 二级菜单「景点管理」「旅游数据大屏」；
- 9 个按钮权限（查询/新增/编辑/删除/综合推荐/热门排行/相似推荐/统计聚合/地区列表）；
- 授权给「管理员」角色。

## 六、前端功能实现

### 6.1 景点管理页面（`web/src/views/tourism/scenic/`）

基于 **FastCrud** 低代码 CRUD 组件实现，`index.vue` + `crud.tsx` + `api.ts` 三文件分工：

- 列表分页展示景点信息，支持按名称/地区/等级搜索；
- 图片列缩略图预览（`el-image` + `preview-src-list`）；
- 标签列解析 JSON 后以「/」拼接展示；
- 详情页列提供外链跳转；
- 行内新增/编辑/删除，按钮按权限控制显隐。

### 6.2 旅游数据大屏（`web/src/views/tourism/recommend/`）

基于 **ECharts** 实现可视化大屏：

1. 顶部 4 个指标卡：景点总数、平均评论分、平均热度、累计评论量；
2. 柱状图：热门地区景点数量 TOP10、热门标签 TOP10；
3. 饼图：景区等级分布、门票价格区间分布；
4. 榜单：综合推荐 TOP10、热门景点排行 TOP10（含缩略图）。

## 七、环境配置与部署

### 7.1 后端配置

```bash
cd backend
cp conf/env.example.py conf/env.py          # 配置 MySQL（root/123456）
# 新建数据库
CREATE DATABASE IF NOT EXISTS `django-vue3-admin` DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
# 创建虚拟环境并安装依赖
python -m venv venv
venv\Scripts\python.exe -m pip install -r requirements.txt
# 迁移与初始化
python manage.py makemigrations
python manage.py migrate
python manage.py init
# 导入旅游数据
python manage.py import_scenic
# 启动后端（8000）
python manage.py runserver 0.0.0.0:8000
```

### 7.2 前端配置

```bash
cd web
npm install --legacy-peer-deps --registry=https://registry.npmmirror.com

# .env 已配置 VITE_API_URL = 'http://127.0.0.1:8000'
npm run dev        # 启动前端（8080）
```

## 九、遇到的问题与解决

| 问题 | 原因 | 解决方案 |
|---|---|---|
| `manage.py init` 报 `Unknown column 'name_en'` | 框架自带 system 迁移较旧，缺少 i18n 列 | 先 `makemigrations`（全量）再 `migrate` |
| `npm install` 报 eslint 依赖冲突 | eslint 9 与 @typescript-eslint 5 的 peer 冲突 | 加 `--legacy-peer-deps` |
| 前端编译报 `Could not resolve @vxe-ui/core / dom-zindex` | Node 20+ 未自动补齐 vxe-table 依赖 | 手动 `npm install @vxe-ui/core dom-zindex` |
| Windows 安装 mysqlclient/gevent 失败 | 缺少 C++ 编译器/无对应 wheel | mysqlclient 升 2.2.4；注释 gevent/gunicorn/pyinstaller/psycopg2 |
| 数据导入报 `Column 'name' cannot be null` | 数据集中存在 227 条名称为空的残缺记录 | 导入时跳过空名称记录 |
| 接口无斜杠访问返回 301 | Django 路由自动补斜杠 | 统一使用带尾斜杠的接口路径 |
| 登录报 `Verification code has expired` | 前端登录走 `/api/login/`，读系统配置 `base.captcha_state`（默认 true），不受 env.py 的 `LOGIN_NO_CAPTCHA_AUTH` 影响 | `SystemConfig` 将 `captcha_state` 改为 `False` 后重启后端 |
| 菜单之间无法跳转 | `dvadmin3-celery` 插件与框架内置 celery 菜单重复（taskManage/taskLog 的 component_name、web_path 各重复一次），导致 vue-router name/path 冲突 | 删除插件版重复菜单，新增 `manage.py fix_menu_duplicate` 命令一键修复 |
| 多标签切换异常 | 组件 name 与 component_name 不匹配/重复（`menu` 组件名是 `menuPages`，`demo`/`DeptUserCom` 与登录日志/用户管理重名），keep-alive 缓存错乱 | 组件 name 改为 `menu`/`demo`/`deptUser` |
| 路由重复注册 | `formatTwoStageRoutes` 用浅拷贝保留了目录 `children`，导致每个子菜单路由被注册两次 | 改为 `push({ ...v, children: [] })` |
| 景点管理表格渲染报 `vnodes.some is not a function` | `CustomModelSerializer` 内置的 `modifier_name` 对无审计字段的普通模型返回 `None` | 旅游 serializer 改用原生 `ModelSerializer` + 自定义 `request` 参数 |
| **打开两个以上功能后 URL 变但主体不渲染（最终根因）** | `npm install` 因 `^1.21.2` 自动把 FastCrud 升到 1.29.0，该版本渲染 el-table 单元格插槽时返回 null，报 `vnodes.some is not a function`，所有 FastCrud 表格页崩溃、路由切换后主体卡住 | 锁定 `@fast-crud/*@1.21.2`，配套 element-plus@2.8.8、vue@3.4.38 |

## 十、总结与展望

本项目基于 django-vue3-admin 框架，完成了旅游推荐后台管理系统的完整建设，实现了「**数据导入 → 数据管理 → 推荐接口 → 可视化大屏**」的端到端流程，系统前后端均可正常运行、可访问。

**主要成果**：
- 完成 48,127 条真实旅游景点数据的结构化入库与管理；
- 实现综合推荐、热门排行、相似推荐三类推荐接口；
- 实现 ECharts 可视化大屏，直观呈现数据分布与推荐结果；
- 落地了框架的 RBAC 权限、菜单动态加载等机制。

**可扩展方向**：
1. 引入更复杂的推荐算法（如协同过滤、基于地理位置/用户画像的个性化推荐）；
2. 增加景点图片本地化存储、评论情感分析；
3. 接入 Celery 异步任务实现大数据量导入的进度可视化；
4. 使用 Redis 缓存热点数据，优化大屏查询性能。
